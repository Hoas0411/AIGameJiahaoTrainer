# 嘉豪训练器：游戏模型修改与画面校准流程

> 状态：canonical · 层：organization · 真相域：jiahao_model_modification_procedure  
> 上位：[项目规则](../../AGENTS.md)、[场景与资源契约](../architecture/jiahao-trainer-scenes.md)、[制作底座素材方法](../../../../ai-game-workbench/production/methods/asset.md)  
> 实例与验收：[M7 瞄具重建记录](../inspection/jiahao-m7-model-rebuild-2026-09-25.md)

本文回答“在嘉豪训练器里怎样修改一个已有模型，并校准它在游戏相机中的画面”。它不改变模型、武器行为或工作台的所有权；通用素材要求以上位规则为准。本流程来自 2026-09-25 用户通过的 M7 第一人称瞄具迭代。静态场景模型使用相同的图纸、Blender 和导入步骤，但不套用第一人称的持枪位姿参数。

## 1. 先找唯一编辑入口

| 要改的东西 | 编辑位置 | 不作为编辑源的东西 |
| --- | --- | --- |
| 三维形状、独立零件、材质 | `apps/jiahao-trainer/source_art/<资产>/` 中的 Blender `.blend` | Godot 原语、运行时造网格、`.godot` 导入缓存 |
| 运行模型 | 从最终 `.blend` 导出的对应 `.glb`；M7 为 `resources/weapons/m7_model/m7.glb` | 旧交付包或归档中的模型 |
| 第一人称位置、角度、动作和镭射 | `scenes/weapons/weapon.tscn` 与 `scripts/weapon.gd` | 改模型顶点来凑屏幕坐标 |
| 枪械数值 | `resources/weapons/*.tres` 和 `scripts/weapon_profile.gd` | 在模型或截图分析脚本里复制数值 |
| 结果证据 | 本次 `evidence/` 截图、工作台回执及 `docs/inspection/` 验收记录 | 把“机器通过”写成“人已认可” |

修改前读取 `apps/jiahao-trainer/AGENTS.md`，从该工程运行 `./tools/workbench.ps1 context --profile asset`，按清单读规则。Blender 源模型属于 `asset` 任务；共享武器脚本与运行资源属于说明影响范围和恢复方式的 `integration` 任务。两段任务分别 `begin → 修改 → check → finish`；需要全局冒烟时显式 `check --engine`，本次武器的真实专项验证仍不可省略，不要在素材任务的写入范围内顺手改共享武器脚本。

## 2. 先截基线，再画两级分析图

使用参考和当前游戏**相同分辨率、相同瞄准状态、可比较的视角**截图。至少覆盖普通持枪、正镜瞄准和侧瞄/镭射；动作另取几个关键帧。记录分辨率、FOV、相机状态和每张图的来源，不用不同分辨率的原始像素直接相减。

1. **大体分析图：** 画水平、垂直中心线，将画面四分；标出枪口、瞄具中心、握把、手、枪身最近边缘等关键点的像素坐标。沿枪身画长轴和边界辅助线，比较屏幕占比、长度、斜率与高低。先确定哪个偏差属于整枪位姿，哪个属于零件尺寸。
2. **细节分析图：** 放大关键结构，逐件描出轮廓和接口，标注上下左右边界、像素宽高及文字判断。例如瞄具是否开放、立柱是否向内成 V、下支架是否真镂空、侧面旋钮几个、镜片是否有墨镜般的深色、下方枪体在指定 y 坐标处有多宽。可见事实与推测分开写。
3. 把图纸的尺寸落实到 Blender 的零件尺寸与游戏相机位姿。图纸正确但实装形状不同，视为未完成；先改对应零件或位姿，不用整体扭曲蒙混。

## 3. 在 Blender 中改真实几何

从用户已认可的枪身基线打开 `.blend`。保留无需修改部分的拓扑和物体变换；仅删除要重做的旧部件，并以独立网格构造立柱、前板、镂空支架、底座和控制件。零件有真实厚度、倒角及相互接口。开孔必须是几何上的通透区域，不能用深色贴图假装；不通过拉伸整个旧瞄具或按屏幕比例扭曲枪身来补图纸差距。

保存新的可编辑 `.blend`，导出 `.glb`，登记源文件、参考图和修改要点。用 Blender **实际打开最终保存的 `.blend`**，留界面截图；仅有后台导出日志不算这项证据。材质、法线、正反面、对象层级、方向和尺寸都要在 Blender 及导入后的 Godot 中分别检查。

## 4. 接入游戏并按偏差类型迭代

素材任务通过后，再建 integration 任务，将最终 GLB 接入原有资源路径，更新来源登记。先用整枪**刚性平移与旋转**校准枪口、瞄具中心和枪身走势；整体一致的等比例展示尺寸可以另行校准，但不得对某一轴做非等比缩放，或对枪身和瞄具分别反向缩放以制造假比例。手部、枪口特效和镭射发射点须随实际枪体保持一致。

在 Godot 中重新导入资源，运行游戏截图，并把三种状态与图纸再次按相同像素坐标比对：

- **枪口与瞄具一起偏移：** 优先改整枪位姿；普通持枪和开镜分开校准。
- **枪口对了，瞄具的宽、高或开孔不对：** 回 Blender 改对应独立零件的 CAD 尺寸；仅移动整枪无法同时修好远近透视比例。
- **开镜立柱、前板、下支架的 y 区间不对：** 对照细节图分别调整零件高度和整体开镜位置，不压扁整个模型。
- **近处枪体过宽而远处瞄具过小：** 这是透视和零件比例的组合问题；记录两个截面的宽度，分别试刚性深度与零件真实宽度，不对机匣做横向压缩。
- **镭射方向与枪口不符：** 查实际发射器在枪体哪一侧、局部轴朝向及射线的世界方向，并在游戏画面确认光束。

每轮只保留可解释的改动与试拍。失败就标出未通过的点并做下一版；不能把一次失败当作整个任务结束，也不能删除失败证据来获得通过。镜头效果、几何结构、材质和手部接触分别验，机器检查不能替代看图。

## 5. 验证与交付

素材和集成各自运行工作台 `check`（全局冒烟显式加 `--engine`），只有对应源码的回执通过且新鲜才 `finish`。再执行目标武器的游戏内验证、三状态截图和必要的声音/动作关键帧复核。把最终 `.blend`、导出 GLB、设计图、Blender 打开截图、游戏截图、来源登记、回执和未通过项相互链接。用户明确说“通过”时，在 `docs/inspection/` 记录接受日期与适用版本；不改写机器回执中的 `pending_human` 字段。

只有产生新的完整交付包时才按项目规则登记版本、验证归档独立性并归档超额旧包；唯一源文件、原始参考和必要依赖留在活动目录。

## 6. 新枪械、手部与证据补全（规则整理，2026-10-08）

本文件是 `weapon` 流程唯一正文；入口见 [素材与枪械AGENTS](D:/Codex/agents/素材与枪械/AGENTS.md)。已认可证据只覆盖上列 M7 第三轮模型及姿态，不自动认可其它枪械。M7 的像素值、位姿和零件数量是实例参数，不是所有枪的固定规格。

新枪没有认可基线时，先按参考形成整体比例、三状态大体/细节分析、独立零件与接口图，再进入 Blender。已有枪从用户当前认可的活动源文件开始。按明确授权制作；指定付费生成路线另按本次图纸批准与费用授权执行，不能把箱体R3配方当枪械已验证结果。

手套/衣袖外观、握持姿态和动画轨道分别处理：用户只改姿态时不替换认可外观。手与枪核对相机层、FOV、整体尺度、接触点，避免重复手、巨大前臂和穿插；动作轨道必须驱动实际可见手部。依据 `武器-建模与修改` 聊天（2026-09-26）的明确纠正：同一外观不代表同一握姿，不能复用旧占位手替换。该纠正是保护约束，不宣称后续手部修复已获认可。

禁止用非等比缩放或网格轴向拉伸凑截图；同时检查整条实例/父级矩阵与源网格，相同 Scale 不足以证明。合法独立零件重建需回尺寸图，不混称对原枪身的无变形校准。

静态至少普通持枪、正镜、侧瞄/镭射；受改动影响的动态检查射击、后坐恢复、空仓/战术换弹、拉栓、切枪、走跑、落地与歪头，并在近墙和无遮挡位置对照。没有该功能的项注明不适用及依据，不硬造功能。武器数值、声音及共享功能回归按实际影响选择，画面与手感另验。

按 [共同验证与证据协议](D:/Codex/ai-game-workbench/production/methods/modeling/verification.md) 填写 weapon 自检清单并运行检查。设计、.blend、Blender界面、最终GLB与运行资源的哈希、三状态实机图及材料/几何对照应能互相追溯；源或运行文件变化后重新取证。自检通过可交用户评价，不代签用户满意。
